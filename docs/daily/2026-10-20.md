### Data Agent 与 ChatBI 的分水岭：查 vs 做

Data Agent = LLM 大脑 + 数仓手脚，覆盖三层：消费侧（问数/归因/报告）、平台侧（元数据/血缘/质量）、研发侧（ETL 生成/管道编排/异常诊断）。与 ChatBI 的分界不在能力强弱：**ChatBI 止步于"查"（人找数），Data Agent 强在"做"（写回/建管道/改配置，数找人）**。

### 六层架构：LLM 只做规划，确定性交给工程

L1 智能编排（LLM 规划，**全栈唯一 LLM 层**）→ L2 工具接口（MCP 事实标准）→ L3 确定性引擎（零 LLM：校验/翻译/执行/渲染）→ L4 本体语义层 → L5 记忆层 → L6 观测层。工程原则一句话：LLM 管理解与规划，执行链路全部确定性。

### NL→MQL→SQL 两段式

理解侧 LLM 只生成纯业务语义的 MQL——**出现物理表名/字段名=格式错误直接拒绝**；执行侧零 LLM 规则翻译成 SQL。LLM 永不直连物理模型，这是幻觉的第一道闸。

### 记忆三层：口径文档做 RAG 是企业最普遍路径

工作记忆（上下文窗口+scratchpad）/ 情景记忆（向量库会话摘要）/ 语义记忆（知识库+语义层 RAG）。企业落地最普遍的做法不是炫技，是把**口径文档做 RAG**——语义资产先行。

### 两个反直觉的市场观察

厂商卖的是引擎，**口径（语义模型）永远要自己建**——买 Databricks/Snowflake 也不例外。Vanna.ai 的经验：问答对是最值钱资产，**冷启动人工写 50 个高质量 QA 比调 prompt 有效**。
