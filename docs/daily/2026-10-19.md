## TIL

### 执行签名投票：让数据库当裁判，不请第二个 LLM

DataFlow（SIGMOD'27，OpenDCAI）的 text2sql 质量方案：CoT 生成 N 个 SQL → **全部在真库执行** → 把每个结果集转成 `frozenset` 签名 → 多数决定稿。为什么不用 LLM 评卷：LLM 评 LLM 有同源偏见，数据库执行是**确定性外部信号**。SQL 人的翻译：结果集全等比较当唯一裁判，比自评可信一个量级。

### 难度 = 通过率统计，不用人标

同一题生成 10 次，按执行成功次数 2/5/9 分档 extra/hard/medium/easy。质量与难度标签全部统计化——这套思路对"报送口径变更影响面评估"也适用：跑 N 次看通过率，比拍脑袋分档硬。

### Pathway 建在 timely-dataflow 上，且全仓无 watermark

62k⭐ 的 Pathway 引擎不是自研底座：`src/engine/frontier.rs` 第一行 `use timely::progress::Antichain`——直接用 timely 库（McSherry 增量计算一脉）。全仓 grep watermark 零命中：没有事件时间语义，模型是"到达即处理 + 增量重算 + 最终一致"。**Flink 老兵的一句话判断：物化场景（实时看板/RAG 索引自动更新）它是新答案，乱序窗口风控流仍属 Flink**。另外 BSL 1.1——源码可见≠开源，代码一行不能搬。

### HITL 可以做成"工具级配置表"

ERP-AGENT（120⭐ 企业采购 Agent 样本）的人工审批：LangGraph 原生 `interrupt_on`，配置粒度到 `{工具名: {allowed_decisions: [approve, reject]}}`——哪个工具要审批、允许什么决策值，一张表说完。配套还有 needs_revision 自动打回的 Review 回路、三行常量的预算护栏（MAX_MODEL_CALLS=50/85% 上下文自动摘要）。
