### LLM Wiki vs Ontology：语义放哪

一句话分野：**LLM Wiki 是写给 LLM 读的活笔记，语义靠模型当场理解（概率性）；Ontology 是写给机器推理的形式化地基，语义写死在结构里（确定性）**。互补不是替代——Wiki 擅长隐性知识、踩坑、口径故事，建设成本低；Ontology 擅长跨系统对齐、机器校验、grounding，建设成本高。

### 两条消费链路对比

Wiki：提问 → 检索（相似度+显式链接）→ LLM 读文本 → 答案，语义在模型脑内。本体：提问 → SPARQL/推理机 → 公理演绎 → 结论，语义在结构里，**结论可证明**。

### 混合趋势：谁也吃不掉谁

LLM 建本体（qOntology 四轮对话建模，门槛从本体工程师降到会聊天）；本体喂 LLM（形式化模型做 grounding，确定性 37%→98%）。选型口诀：**记经验、容忍模糊 → Wiki；跨系统对齐、要机器可判 → Ontology**。
