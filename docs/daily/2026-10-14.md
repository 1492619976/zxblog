### print ≠ return：喊一嗓子 vs 交货签收

`print` 把东西打上屏幕就没了，调用方**什么都接不住**；`return` 才是把结果交还给调用者、能被 `x = f(...)` 装进变量的动作。没写 `return` 的函数，Python 自动返回 `None`——所以 `x = f1(100)` 之后 `x` 是 None，不是"f1(100*2)"。

PL/SQL 一秒对照：`DBMS_OUTPUT.PUT_LINE` 打印满天飞、宿主程序一行拿不到；只有函数 `RETURN` 的值才能被赋值。函数要交结果，必须 return。

```python
def f2(n): return n * 2     # a = f2(100) → 200（接得住）
def f3(n): print(n * 2)     # b = f3(100) → None（喊完就没）
```

### hash 是什么：快递柜取件码

hash = 把任意数据压成一个固定长度的**编号**（同输入永远同输出），查找时按编号**直奔柜子**，不用挨个翻——Java HashMap / Python dict / Oracle 执行计划里的 HASH JOIN 是同一招数的三套马甲，1953 年就有了，比这两门语言都老。

两条关键推论：

- **dict 的键必须不可变**：编号按内容算，list 当钥匙会变形（append 之后内容变了编号变了，柜子就找不回）——tuple 石碑不变形，编号终身稳定。实测 `hash([1,2])` 直接 `TypeError: unhashable type: 'list'`，"不能 hash"和"不能当 dict 键"是同一件事。
- **hash 只带路不判等**：查找两步走——先 hash 定位柜子（管快），再在柜内用 `==` 验明正身（管准）。hash 相等 ≠ 内容相等（会碰撞）。这就是"is 和 == 都不比 hash"的完整含义。

### 运算符也认身份：`-` 是 set 的专属技能

`list - list` 直接 `TypeError`——差集是 **set** 的专属运算，list 只有 `+`（拼接）。对账函数里要先 `set(a) - set(b)` 换身份再相减，顺手把重复也去了。符号识别表的延伸：**不光记号认身份（`[]` list / `()` tuple / `{k:v}` dict / `{v}` set），运算符也认身份**。

### 缩进的真正规则：层级对齐，不是"有缩进就行"

两条规则：**同级兄弟站一排**（`try` / `except` / `finally` 是平级柜台必须对齐同一列）；**进一层右移 4 格**。层级地图 0/4/8/12 梯队：

```python
with open(path, "r", encoding="utf-8") as f:   # 0 格
    for line in f:                              # 4 格
        if "ERROR" in line:                     # 8 格
            print(line)                         # 12 格
```

### 文件三坑：w 瞬间清空、忘 close 一鱼两吃、读文件不是 a

- `"w"` 模式**打开的瞬间清空整本文件**（不是"写的时候覆盖"）——续写日志永远 `"a"`。
- 忘 `close` 两个后果：① Windows 锁文件报"被占用"；② **write 先进缓冲区，close 时才真正刷盘**——最后一笔可能根本没落盘。这正是 `spool off` 的完整含义：不 off 文件既是被占的、又是断的。
- 读文件写 `"a"` 模式直接 `io.UnsupportedOperation: not readable`——`a` 是追加写、压根没有读权限，读必须 `"r"`。

### with 的真面目：它不负责"记住文件"

我一度以为"不用 with 就不知道读哪个文件了"——错。`f = open(...)` 里的 `f` 标签本身就贴着文件对象，知道是哪个文件。**with 的唯一作用 = 出块自动 close，哪怕中途出异常也会关**（= Java try-with-resources）。归还靠制度不靠记性。
