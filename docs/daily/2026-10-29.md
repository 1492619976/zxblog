### Agent 长程任务：四扩展机制选型表

Skills（提示词规范）/ SubAgents（独立工人）/ Teams（对等协作）/ Dynamic Workflows（JS 脚本编排）。两个判别维度：**谁决定下一步**（前三者都是主 Agent 逐轮思考，Workflow 是脚本代码）、**中间结果存哪**（前三者靠上下文，Workflow 是内存变量）。结论：步骤固定、过程需追踪、结果需复核的长程任务 → Workflow。

### 单 Agent 跑长链条的三类失败

①**自行缩小任务范围**（见数据量大就判"没必要"跳过，不报错流程照走）②**关键约束在上下文传递中丢失**（前序要求的稳健性检验，报告节点没带上——"不是错而是漏"）③**有返回结果 ≠ 执行正确**（定了"合成对照"却直接跑 DID，每个节点都交了卷但不是同一套方法）。根因统一：计划、中间状态、校验责任全靠主 Agent 在上下文里自维护。

### 对抗验证：验证者与执行者分离

Workflow 末段放一个独立 Agent 逐条找茬，`return state.check.ok ? state.report : fix(state)`——自己查自己靠不住，让另一个上下文干净的实例查。

### 问数 Skill 的四点不同

问数场景"要准、要稳定复现、要快"（少一个小数位是致命的），所以：①不能使用纯文本操作指令 ②要配套 MCP 工具与数据底座交互 ③要配一整套硬编码校验脚本 ④要配编译执行引擎——**声明（SKILL.md 五件套）与代码（engine/framework）分离**。金句：思维链是二维的（从前到后），**Skill 是三维的（树形展开、按需调用）**。
