## TIL

### git 并行血统：API 断流期重推的链和本地不是一家人

GitHub 断流那几天用 Git Data API 推过一批提交——API 通道是把文件重新上传再拼 commit，**和本地原生链是两条没有共同祖先的并行血统**，push 直接被拒（non-fast-forward）。对齐三步：

1. 先验证内容等价：`git diff --ignore-cr-at-eol main github/main` 为空 = 差异全是换行符口径（API 通道 CRLF/normalize 所致）
2. 再 `--force-with-lease=main:<远端SHA>` 强推——比裸 force 多一层保险：远端在你操作间隙又动了就拒绝
3. 结论：**内容等价时保留本地真源血统**，提交信息还是原来的中文原生版

类比：两条分支像同内容的两个副本库，`--ignore-cr-at-eol` 是"去空格比对"，lease 是" optimistic lock"。

### 开源前脱敏：把"我的约束"改写成"示例配置"

fitness-coach skill 转公开前的脱敏流程：伤病约束从"我的诊断"改成"示例配置（按自己情况改写）"框架；删个人体重目标/时间线/就医待办；热量口径改"按个人计划设定"。**私人版约束留在 vault 计划文件里永不公开，skill 运行时读的是它——公开的只是说明书**。发布类 skill 的标准动作。

### GitHub 仓库可见性一条 API 命令

`PATCH /repos/{owner}/{repo}` 带 `{"private": false}`，token 从 `git credential fill` 取（GCM 存量凭据）。今天六个仓全转公开，API 通道全程稳定（主站 443 又断流了，api.github.com 恒稳这个规律第三次应验）。
