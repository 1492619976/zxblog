## TIL

### `__name__` 是 Python 发给每个文件的工牌

直接运行本文件 → 工牌写 `"__main__"`（我是主角）；被别人 `import` → 工牌写文件名（我是零件）。`if __name__ == "__main__":` 就是问"我是不是主角"——自测代码放门卫里面，被导入时永远不执行。三连实验验证（同一文件直接跑输出 `__main__`、被 import 输出模块名、加门卫后自测闭嘴）。Java 天生只有 main 是入口没这烦恼；Python 任何文件都能直接跑，所以要自己安门卫。**读任何开源项目都从这行下手。**

### 魔法方法 = Python 保留的暗号机关，运算符只是糖衣

双下划线包围的名字（dunder methods）是 Python 自带的机关：名字是保留暗号，**特定时机 Python 自动调用**。实测拆穿三件事：

- `dir(list)` 看到每个类型出厂自带一排机关
- `"a" + "b"` ≡ `"a".__add__("b")` —— **运算符进门先找对应机关**
- list 有 `__add__` 没装 `__sub__`，set 装了 —— 所以 `list - list` 报 TypeError、`set - set` 能算差集。之前"运算符认身份"的错题，底层拆到零件了

### `__str__` 删掉 return 不是打出 None，是直接 TypeError 掀桌

实测预期外发现：`__str__` 里只写 `pass`，`print(对象)` 报 `TypeError: __str__ returned non-string (type NoneType)`——Python **强制名牌机关必须递出字符串**，比想象中严格。实测又一次比讲解更硬。

### 两机关门铃模型：__init__ 装修队、__str__ 名牌

OOP 写类三轮鏖战的最大教学发现：Java 转过来的最容易把两个机关搞混——**装家具的代码写进名牌房间**。拆法：类里只有两个门铃，门铃 1「新房落成」→ 自动跑 `__init__`（装家具 `self.name = name`，不 return）；门铃 2「有人 print」→ 自动跑 `__str__`（递纸条，**必须 return 字符串**）。另一个高频坑：类内部访问自己的属性必须报门牌 `self.name`，裸写 `name` 实测直接 `NameError`——家具挂在实例身上，进门不报门牌找不到它。

### 类名赋值 = 改公司规范，全体立即生效

类属性是所有实例**共享的一份**。`Customer.source = "征信"` 是改规范——没单开小灶的实例全部跟读新值；`c1.source = "反洗钱"` 才是 c1 单开小灶（遮蔽）。查找规则一条合并：**读 `实例.x` 先翻这家的小灶（实例属性），没有再去看公司规范（类属性）**。这是"就近相欺"家族的第三例（前两例：实例遮蔽类属性、random.py 遮蔽标准库——同一套机制）。

### f-string：f 前缀让大括号算数

`f"任务[{self.name}]"` —— f = "字符串里的大括号要算数"，`{变量}` 就地塞值 ≈ Java 的 `String.format`。打印对象名片的标准姿势。
