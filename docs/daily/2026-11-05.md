## TIL

### 本体 grounding：确定性 37% → 98%

无约束 GPT-4 临床 QA 37%、R1 52%；本体 grounding 后 **98%**，无 grounding 幻觉率 15~25%。三层确定性对位拆解：**词汇确定性**（术语绑唯一概念）/**结构确定性**（schema 约束生成空间）/**计算确定性**（数字从模型手里拿走，规则引擎算）。该确定的交给确定性，只让模型做理解与组织。

### 知识更新两层区分：Agent 记忆 ≠ 企业知识

Agent 记忆是个人化的、可自动沉淀；**企业知识必须资产化、走受治理更新**——别把企业知识塞进记忆框架。语义层更新走"候选-采纳分离"：AI 起草带证据 → 人工评审 → 采纳发布，知识像代码走"草稿→评审→发布→版本"流水线。

### Agent = 模型（上限）+ Harness（下限）

Claude Code 仅 1.6% 代码是模型交互、**98.4% 是驾驭层**。落地方法论压缩成一句：Harness 管确定性、记忆管长期一致、取数 Skill 管流程资产化——全在"模型外工程"。

### Protege 变更对象化：免费得 undo/审计

所有模型修改统一走 `applyChanges(List<Change>)`，变更对象**不可变、可自动求逆**，先抵消冗余再原子提交——undo 就是生成逆变更复用同一提交管线。做任何"可回退编辑器"都值得照抄。

### RDF4J 用数仓对照一遍就懂

Sail ≈ 存储引擎；SailSourceBranch+Changeset ≈ MVCC 写时复制；三棵字段序不同的 B-tree（spoc/posc/ospc）≈ 组合索引最左前缀；字典编码（三元组记成 4 个 int）≈ 列存字典；SPARQL 全链路 = JavaCC 文法 → 代数树 → 优化管道（JoinOrder 代价/Filter 下推）→ 火山模型拉取。

### muopt 保形转换三原则

SQL 方言转换**刻意不用 AST**（toString 重排毁格式）：字面量掩码 → 函数映射 → **类型槽位白名单**（只换 CREATE TABLE/CAST 位置的类型词，防列名叫 text 被改成 CLOB）；"宁可漏改不猜"。写回安全五重闸（防穿越/丢占位符即终止/.bak 备份/GBK 严格写回）是防御式小工具教科书。

### qOntology：AI 四轮建模 + 宣传与实现的落差

四轮 LLM 流水线（CQ 术语→对象→属性关系→公理规则）→ 候选表（置信度+证据溯源）→ **人工采纳落正式表**。反面教材同样值钱：质量检查/SHACL/问答全是占位壳——读开源项目要拿源码对 README 逐条核。
