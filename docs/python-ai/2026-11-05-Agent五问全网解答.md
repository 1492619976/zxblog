# Agent 五问全网解答（本体确定性/知识更新/Harness/金融可信/智能取数）

## Q1 本体如何让 Agent 获取确定性结果

- LLM 不确定性三源：词汇歧义/无约束生成/事实不在模型里
- **三层确定性对位拆解**：词汇确定性（术语绑唯一概念）/结构确定性（schema 约束生成空间+SHACL 校验）/**计算确定性（数字从模型手里拿走，规则引擎算）**
- 硬数据：**本体 grounding 临床 QA 98% vs 无约束 GPT-4 37%/R1 52%**；无 grounding 幻觉 15~25%；幻觉四失败模式各需不同检测器；2026 收敛神经符号架构
- 一句话：该确定的交给确定性，只让模型做理解与组织——生成前 schema 约束/生成中类型检查/生成后规则核对

## Q2 如何为 Agent 持续更新企业知识

- **两层区分（答题关键）**：Agent 记忆（个人化，可自动沉淀，mem0/Zep/Letta/Hindsight/Cognee 八框架混战）vs 企业知识（资产化，必须受治理更新）——别把企业知识塞进记忆框架
- **三层更新流水线**：事实层自动流（CDC/T+1，数据流过本体不动）/语义层受控改（**候选-采纳分离**：AI 起草带证据→人工评审→采纳发布）/治理层制度改（本体委员会裁决+版本化+变更留痕）
- 一句话：知识像代码走"草稿→评审→发布→版本"流水线，Agent 只读最新已发布版本

## Q3 办公型 Agent 如何设计 Harness

- 公式：**Agent=模型（智商上限）+Harness（落地下限）**；Claude Code 仅 1.6% 模型交互代码、98.4% 驾驭层；提示词→上下文→驾驭层工程三阶段
- **ETCLOVG 七层**（腾讯开发者）：执行沙箱/工具协议/上下文记忆/**生命周期编排(核心)**/可观测/验证评估/治理安全——目标"概率生成→企业确定性输出"
- 办公特化四条：人是最重要的工具（确认门一等公民）/技能渐进披露三级加载/文档即工作区（planning with files）/护栏前置（权限最小化+发送类二次确认）
- 一句话：七层骨架+把人审批做进编排层+技能做成渐进披露库

## Q4 金融智能体如何可信可靠落地

- **金监总局 2026-06《银行业保险业 AI 安全开发应用指导意见》：可解释性成准入项**（高风险场景可解释性不足仅能有限使用）——最新监管背书，可补进课题材料
- 可信四支柱：确定性底座（数字来自规则引擎）/全程可解释（每个数带公式口径溯源一点到底）/操作可治理（动作=前置规则+权限+留痕，沙箱+审批）/场景分级（先落地重复性高规则清晰场景）
- 落地四步走：监测(只读)→辅助分析(只读+解释)→建议生成(受控写)→受控执行(白名单写逐动作灰度)
- 产业：天融信三关（准入评估/实时网关/运营治理）、点金 100ms 沙箱留痕、可信互联互认框架

## Q5 Data Agent 如何让取数更简单更智能

- 共识：**dbt 语义层+最强模型覆盖查询近 100% 准确**；Cube 定性"Text-to-SQL 给数据访问权，语义层给业务理解"；Neo4j 语义层省 20~30% token
- **三阶段演进**：裸 NL2SQL（进不了生产）→语义层 Agent（生产主力：口径卡资产化，LLM 只懂意图，语义层生成 SQL）→图谱/OAG Agent（沿对象关系多跳取数）
- **五件套闭环**：语义层资产化/两阶段生成+EXPLAIN 校验/检索增强（元数据+术语别名进上下文）/取数护栏（只读+预览+答案附口径)/沉淀闭环（问题→SQL→模板库，高频模板化长尾 AI 兜底）
- 一句话：不是更强的模型写 SQL，而是业务语义资产化交给 Agent 查、SQL 交语义层生成、模型只懂意图
