# 腾讯TGR生成式推荐解读（2026-11-04）

## 一句话
TGR（Tencent Generative Recommendation）= 把推荐系统从"逐条打分筛选"（判别式）改造成"像 LLM 生成文字一样直接生成推荐结果"（生成式）。三条路线：GenRank 换排序引擎、GenRec 端到端生成、Reason 借大模型推理救冷启动。已覆盖新闻/视频/小说等 10+ 场景。

## 背景：级联架构与三大瓶颈
- 级联：召回(百万→千)→粗排→精排→重排，每级独立 DLRM（特征查表+人工交叉结构+MoE 打分）
- 瓶颈①：无 scaling law，加参数加算力效果饱和；②：逐条打分 ≠ 整屏最优（列表兼容性/多样性/位置效应刻不出来）+ 层层截断信息损失、各阶段目标割裂；③：协同信号只管"记忆"不管"推理"——新用户/长尾 item/意图模糊三场景失效
- 业界坐标系：Meta HSTU（首个可信 scaling，万亿参数 A/B +12.4%）→ 快手 OneRec（端到端生成首个工业化）→ 腾讯 TGR

## 全文钥匙：SID 语义 ID
- RQ-VAE 把物品内容向量量化成 D 层 coarse-to-fine 码字（类比图书分类号 TP311.13），语义相近共享前缀
- 推荐 → 预测下一个 SID 序列，与 LLM 预测下一个 token 同构，可复用 Transformer 骨干/scaling/推理基建
- 但语言自回归 ≠ 推荐自回归：BARGE 修 token 语义与序列结构缺口，HiGR 把生成单元升级为整屏

## GenRank（重塑路线：级联不动，换排序 backbone）
- CCFormer 三件套：特征域分离 cross attention（复杂度 O(L) 线性）+ 子空间 token mixing（避开 O(L²)）+ 层级卷积压缩（先交互后压缩，不前置）
- 效果：40 亿样本 AUC 77.94 / GAUC 71.36 超 HSTU，GFLOPs 仅其 3~6 成，训练提速 2.21×；规模与序列长度两个维度 scaling 斜率更陡（0.5K 序列≈HSTU 2K 序列效果）；5 场景 A/B 显著，已推全

## GenRec（替换路线：端到端生成）
- **BARGE**（NTP 范式，生成单个 item）：
  - Item Boundary Gap = SID 展平后边界丢失 → ICA 聚合 item 级上下文门控注回
  - Semantic Drift = 前缀错则后续全错（前缀对准确率 77.0% vs 错 0.6%，差 128 倍）→ HPR 累计路径一致性重排 beam + InfoNCE 难负样本（NTP 高概率错误前缀/曝光未点击）
  - DPD 双通路解码 soft-OR 融合（两路 Top-10 Jaccard 仅 0.17，互补）；OSQ-VAE 正交旋转产出两套 SID
  - 业务：小说场景全量，CTR +0.60%、阅读时长 +1.70%；Hit@5 vs OneRec +10.2%/+16.9%；部署两模式=小 quota 直出 50 item / 大 quota 50 SID 种子×ANN 扩展≈480
- **HiGR**（NSP 范式，生成整屏，CIKM 2026 Oral）：
  - PCRQ-VAE：前缀对比约束只加前 D-1 层（碰撞率 2.37%、一致性 66%；约束到叶子层碰撞×4=身份坍缩）+ 全局量化损失抗残差坍塌
  - HSD 粗到细：14 层规划器（定整屏意图）+ 2 层共享生成器；12+4→14+2 时延 -26% 而 NDCG 仅 -0.6% → 算力该投在规划不在逐 item 解码
  - ORPO listwise 对齐：DPO 要参考模型显存翻倍、GRPO 要在线反馈（推荐离线没法实时把 G 个列表推给用户）→ ORPO 单模型一次前向；三元负样本=乱序（排序保真）/曝光未点击（真实兴趣）/同质 top-k（惩罚信息茧房）
  - 推理工程：Flash Attention + Memory Beam（beam 折叠进序列维 GEMM）+ KV Cache，提速 5×
  - 业务：腾讯新闻/QQ 浏览器小说推全；CTR +0.68%、广告收入 +0.56%、人均观看时长 +1.14% 等

## Reason（快慢思考：借 LLM 推理，推理开销不上线）
- 难点：推荐延迟预算数十~百 ms vs LLM 推理秒级（差 1~2 个数量级）；成本随曝光线性涨；样本漂移要小时级更新 vs LLM 周级重训
- **LatentRec**（隐空间"思考-生成"一体，CIKM 2026）：训练期展开 K=2 步隐向量 rollout + PRL 逐步监督首层 SID + STS 软 token bank 解决尺度不匹配（隐状态范数 45 vs 词表 embedding 3，差 14 倍）；生成期 K=0 直接解码——推理开销归零，10.80s→0.59s（1/18）且 HR@10 反升；可训练参数 <0.2%（Qwen3-1.7B + LoRA16）
- **TGR-Reason 系统**（快慢模型 co-design）：Think 模型离线推理物化 reason tokens → Reason Store（在线点查/近线按需刷新/离线兜底三层，按 user_id）→ GMR 注入 encoder（reason token 当 query 检索"推断意图后群体通常看什么"）+ DRI 注入 decoder（层级对齐 soft prompt，不增加 beam 搜索空间）
- 效果：全量 Hit@1 +28.2%；**冷启动用户 Hit@1 +477.8%**（0.0451→0.2606；新用户协同信号为零，推理先验最值钱，且基数小相对值才这么大）；线上 A/B 新用户曝光-转化 +13.09%

## 对数据工程师的映射
- reason tokens 离线物化 + 在线点查 = 夜批预计算宽表 → 白天即席查询，同一个"贵计算离线化"思想
- 级联逐级截断信息损失 ≈ ETL 逐层过滤，上游删了下游找不回
- 生成式替代判别式检索：与 NL2SQL 从"检索"到"生成"的演进同构
- 快慢思考（System 1/2）+ 推理成本控制 = DataAgent 同款架构问题（贵推理离线做、线上只查）
- 第五方向 TGR-Loop（多智能体自进化推荐）尚在研究期，展望项
