# 2026-11-19 LLM Wiki与RAG区别

一句话=**知识要不要"为模型重写"**：RAG 原文不动、切块后按语义相似度捞（概率匹配，语义在向量空间）；LLM Wiki 入库前先蒸馏成一页一主题的原子页面+显式 **链接**，Agent 用 grep/索引精确检索、顺链接多跳（语义在页面结构里）。

## 六维对比
- 知识单位：chunk 片段(500~1000token+overlap) vs 原子页面(一页一主题)
- 加工：原文直接切不重写 vs 入库前人工/AI 蒸馏重写
- 检索：向量相似度 top-k（概率） vs grep+索引+链接跳转（精确，主键直查式）
- 多跳：弱（靠多轮检索） vs 强（顺 **链接** 走）
- 维护：入库自动省人 vs 每条要人写+登记（维护税）
- 失败模式：相似≠相关/碎块丢上下文 vs 页面过时/漏登记 → 兜底=登记表+lint
- 总纲：RAG=检索层增强（不动知识动检索器）；Wiki=知识层增强（不动检索重写知识）；生产常两手都要

清溪镇类比：RAG=林老师图书馆把书撕碎页按"听起来像"抓一把；Wiki=老陈把心得写成一张张卡片编目录牵线，直接翻卡顺藤摸瓜。

## 八种同类架构（组织轴=知识放哪）
- **放上下文**（用时取回）：Naive RAG → Hybrid RAG(BM25+向量/rerank/HyDE/RRF) → GraphRAG(实体图谱+社区摘要，全局关系问题) → Agentic RAG(LLM 自主多轮检索，Deep Research 同源) → 长上下文(全塞，贵+大海捞针衰减) → CAG(KV 缓存预载) → MCP 工具调用(实时知识)
- **放结构**（语义固化 LLM 只查询）：语义层(指标卡片库/dbt/Cube，NL→指标→SQL 两段式=智能问数正解)；知识图谱+本体(三元组+公理，grounding)
- **放权重**：微调/持续预训练(更新贵、不可溯源)
- LLM Wiki 定位=放上下文族的特例：Agentic RAG 把检索对象从向量库换成原子化知识库

## 身边的例子
- ZCode 记忆层（AGENTS.md 入口+MEMORY.md 索引+原子记忆+**链接**+grep+登记表+lint）= LLM Wiki 完整落地
- 掌柜智库 doc RAG（导入7节点/检索5步/dense+sparse/HyDE/RRF）= Advanced RAG
- 智能问数 = 语义层路线

选型：海量原文常变要溯源→RAG(+rerank)；Agent 长期记忆口径经验→LLM Wiki；精确取数→语义层；跨系统机器可判→本体；全局关系→GraphRAG。
