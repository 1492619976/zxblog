# 17 掌柜智库解读要点速记（doc RAG 全链路）

> 完整解读：`E:\AI解读文档\17-掌柜智库\`（解读.md + 图解讲义.html v1.0）

## 骨架（背）
- **双流水线**：导入链 7 节点（入口分发→MinerU转MD→VLM图片增强→切块→主体识别→BGE-M3向量化→Milvus入库）+ 检索链 5 步（主体确认改写→三路召回→RRF→Rerank断崖→生成SSE）
- 问数=db RAG（检索元数据生成SQL）；智库=doc RAG（检索片段生成答案）
- 通用 RAG 骨架：离线加工（解析→增强→切片→向量化→入库）+ 在线漏斗（理解→召回→融合→精排→生成）——任何 RAG 系统都是这个骨架的变体

## 关键口径
- 切片四原则：语义完整/长度可控/**边界清晰(overlap 10%~20%)**/可溯源；标题粗切+递归细切
- 一文一主体：文档级识别一次回填全部切片（省 LLM+补切片语义）
- 双层索引：kb_item_names(文档级,范围过滤) + kb_chunks(切片级,核心检索)——数仓汇总层+明细层思想
- dense(语义) vs sparse(精确术语/型号/错误码)——BGE-M3 一个模型产两种向量，混合检索双保险
- 三路召回：向量=保基础稳兜底 / **HyDE=补弱意图防漏召**（LLM 编假设答案去检索，答案与文档同语言空间）/ 联网MCP=扩边界
- **分层融合：RRF 只融本地两路，score=Σ 1/(k+rank) k=60，用排名不用分数（量纲不可比）；联网不进 RRF，Rerank 阶段统一合并**
- Rerank 断崖截断：按分数分布拐点动态定数量，不固定 TopN（数据质量异常检测思想）
- LangGraph vs 原生 Agent 五理由：可控/可解释可审计/条件路由在图内/全局状态/可插拔——企业要工作流不要自由 Agent
